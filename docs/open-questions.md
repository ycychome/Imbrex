## 2. 工程探针

| 编号 | 核验内容 | 失败后的动作 |
| --- | --- | --- |
| E01 | Cordis、TS、schema 校验器、Node 与 ws 的实际组合 | 依据证据锁兼容版本，保持契约，不只写浮动 major |
| E02 | SQLite BigInt、事务、worker、迁移与关闭 | 修复实现或绑定，不能降低接纳成功含义 |
| E03 | Linux flock 包装、崩溃释放和插件清理 | 验证目标环境，不绕过锁或凭 PID 猜测接管 |
| E04 | OneBot 服务的身份范围、回复引用、断线和自发回流 | 使用标准路径；必要时增加有测试的小兼容适配或缩小支持范围 |
| E05 | 页大小、队列与并发限额下的内存/延迟 | 按测量调整限额和索引，不提前分区 |
| E06 | 从一种 OneBot 实现迁到另一种时，原生 ID 是否仍同义 | 默认使用新身份命名空间/新插件实例；验证后才允许连续复用 |
| E07 | 所选 pi/pi-acp 的 MCP 连接、ACP 会话恢复、客户端请求与后代进程退出 | 记录实际能力及版本；失败时暂停并修正配置/兼容实现，不假定支持 ACP 就具有全部可选能力 |

所有实现的运行兼容状态从未验证开始。官方声明支持 OneBot v11 只能作为候选依据，不取代我们的标准子集与场景测试。

## 3. 后续触发

自动保留由实际空间需求触发；附件由明确材料目标触发；事件订阅 SSE/反向 WS/HTTP 上报由实际服务与延迟需求触发；MCP stdio、远程 ACP 与更广协议能力由实际消费者触发；更强隔离由故障域或不受信代码需求触发；更换消息底座由实测吞吐或高可用目标触发。MCP Streamable HTTP 和 ACP stdio 已进入 M1，不再作为架构待决项。

OneBot v12 是单独的协议适配任务，不因本版叫 OneBot 就自动进入支持范围。具体实现的私有扩展只有在标准接口不够用且存在实际需求时才启用。

用户无需为上述普通工程选择重新确认；涉及真实账号、动作范围或数据删除的选择，到对应阶段再明确。

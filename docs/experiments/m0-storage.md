# M0 事件与调用存储验证

日期：2026-10-18。覆盖 M0-04、M0-05 的调用记录存储，以及部分 T01—T03/T06 边界；能力分发、HTTP 和正式宿主尚待后续装配。

实现：专用 worker 串行执行完整短事务；主线程最多接纳 32 个未完成数据库命令。数据库实现不向核心暴露 SQL。建库生成持久 store_id，schema_version=1；启动将旧 in_progress 调用置为 unknown。

Node 24.22.0 / npm 11.19.1 下执行 npm run check，新增 6 项针对持久化风险的测试：

- 提交后同步/异步监听失败只记诊断；其他监听和重读仍可见事件，同身份异正文保留首条且不重复通知。
- 字面前缀（含百分号、下划线和大小写）、权限过滤、满页/空页、错误存储标识与超前位置；并发追加不越过单页已捕获上界。
- 关闭重开保持 store_id；序号超过安全整数仍精确；耗尽 SQLite 序号空间时拒绝追加并保留原数据。
- 命令队列满时拒绝超额命令；关闭等待已接纳命令完成。
- 调用记录原子占位、主体隔离、重启 unknown、迟到超时不覆盖成功；不支持的 schema_version 拒绝启动。
- 强制终止真实 worker 后，未完成请求结束且后续请求失败；宿主收到一次失败通知。

SQLite 3.53.4 的 WAL、FULL、foreign_keys=ON、busy_timeout=5000 均在打开时读回核验。编译 lib 使用 ES2024 以声明 Node 24 已提供的 Promise.withResolvers；仍输出 ES2023/ESM。

不由这些测试推出断电耐久、来源完整或外部动作恰好一次。正式启动入口仍须在打开数据库前取得数据目录锁。

# M0 能力调用验证

日期：2026-10-18。覆盖 M0-05/T05/T06 公共机制，不含真实 OneBot 发送。

能力服务只通过 GatewayStore 持久化，provider 通过实例 ID、AbortSignal 与可用性回调绑定。发现和调用按实际主体授权；handler 的事件查询保留实际 caller 的读取范围。已有调用不依赖当前 provider 在线或 schema 再次校验。

独立预期：同主体同 call_id 同参数只派发一次；异参数冲突；首次调用先保存 in_progress；确定结果持久化成功后返回；未知结果不重发；至多 8 个实际执行中的 handler。

Node 24.22.0 / npm 11.19.1 下执行 npm run check。新增 7 项风险测试覆盖：

- 并发同键、对象属性顺序不同、注销 provider 后重试和其他主体查询。
- 超时 unknown、重试不再执行及原执行迟到结果可更新为确定状态。
- 明确失败、抛异常、无效结果分别保持原结果，不因再次请求重复执行。
- 注册冲突、非法参数、权限、只读调用禁止 call_id、禁写与离线状态。
- handler 查事件按实际 caller 的来源权限执行。
- 占位提交失败不调用 handler；结果提交失败不向调用者冒充成功。
- 超时但尚未结束的 handler 继续占用并发额度，避免无限堆积底层操作。

测试使用临时 SQLite 与受控的假副作用。结果提交失败后的原 in_progress 由启动恢复转为 unknown；这不提供平台端恰好一次承诺。

# 应用消费契约

统一开发基线 0.3。本页规定任何应用——进程内插件或进程外程序——如何独立消费事件、如何保存责任状态、以及结果不确定时如何处置。它与具体平台、Agent 或模型无关。

读取规则见[事件与存储](storage-and-recovery.md)，动作结果见[能力契约](capabilities.md)，插件写法见[插件开发](plugins.md)。参考闭环里 `agent-chat` 的 Consumer 细节见[其 README](../../src/plugins/agent-chat/README.md)。

## 1. 三种消费方式

| 方式 | 用途 | 应用承担的代价 |
| --- | --- | --- |
| 临时事件通知 | 控制台显示、短时指标 | 停用、断线或通知失败期间可能漏过，无恢复承诺 |
| 主动读取 + 本地位置 | 简单脚本、可重复计算任务 | 位置保存与业务操作之间可能存在重做或漏做窗口 |
| 读取 + 持久处理状态 | 需要恢复的变换应用、Consumer | 保存本应用需要的责任状态，区分可重做与未决输入 |

插件和外部应用都可自主选择。通知只唤醒读取，不代替持久接手；应用不需要注册 purpose、subscription 或 B1，也没有网关 ACK。

## 2. 输入范围和起点

读取器状态包含 input_id、store_id、source_prefix/type 等实际选择、last_seq。input_id 是应用内部稳定名称，不是网关消费者资源。

新实例先取得 info。面向实时回复的应用默认把当时 latest_seq 作为起点，并原子保存这个明确边界；后续消息从该边界继续读。历史上下文单独查询，不能当作新的触发输入。演示变换和观察器可显式从 0 开始。

恢复使用保存的 store_id/last_seq，不因再次启动而跳到 now。store_mismatch、position_ahead、读取错误或状态损坏使输入暂停并报告，不自动重置。读取选择、来源身份或授权范围改变时，旧位只代表旧范围；不允许静默套用旧绑定。

## 3. 中断和恢复

| 中断点 | 恢复行为 |
| --- | --- |
| 责任状态尚未持久保存，且未执行动作 | 从旧位置重新读取，可再次筛选 |
| 责任状态已保存，但动作可能尚未执行 | 仍暂停；不凭"看起来还没做"自动重投 |
| 已调用能力，但最终响应未到或进度未保存 | 保留未决标记，暂停并人工核验，禁止重跑整轮来补结果 |
| 正常结束与进度已原子保存 | 从新的 last_seq 继续，不重复触发旧输入 |
| 网关调用状态为 unknown | 保留原记录，停止自动补发，不生成新 ID 绕过去重 |
| 应用或网关状态被更换/回滚 | 明确暂停，不声称跨回滚无重复 |

暂停是应用可用性与输入责任状态，不新增 Cordis 的 suspended 状态。诊断应能定位 input_id 与未决事件引用；公开记录对账号和消息标识一致脱敏，不打印正文或凭据。

人工恢复先停用消费者并确认其外部工作已停止，备份当前状态，核对 store_id、输入范围、会话与未决 source/id/seq。结合调用记录及必要的平台证据判断发生了什么；缺少关联时保持未确认，不能把查不到某个猜测的 ID 当作未发生。

操作者明确选择确认已处理或放弃该输入后，记录处置原因，并在消费者停止期间原子更新该输入的 last_seq、清除未决标记；不得借此跳过其他未处理输入。需要补发时按[能力契约](capabilities.md)显式建立新意图并关联旧记录，不自动重播。

单条处置的实际命令见[配置与运维 §6.1](../ops/operations.md#61-单条人工处置consumerrecover)，在线处置的宿主协调流程见[agent-chat §7](../../src/plugins/agent-chat/README.md#m2-recovery)。

## 4. 历史、积压与循环

消费者只对连接器映射的允许入站消息触发。自己发送的回流、派生分析和诊断事件可作为下文，认不触发；不能仅靠 prompt 要求模型不要循环。

配置必须给出自动处理的最大事件年龄。测试默认 5 分钟；按可信来源时间判断，来源时间缺失时使用 accepted_at 并注明口径。超窗输入记录跳过原因并推进；真实使用前明确旧消息策略。

历史预览使用没有外部写权限的凭据或禁写模式。仅添加 replay 标签不能阻止发送。更改旧消息策略不自动清空未决输入、调用或会话记录。

## 5. 演示消费者

fixture-transform 保留位置持久化和读取循环。observer 已删除，原 G05 第二消费者及事件副本交付取消；M0 实验记录保留当时范围。

- fixture-transform 只处理受控 fixture 事件，生成确定内容和稳定派生身份；发布成功后保存位置。崩溃重试同一输出由网关 first-write-wins 处理，不承诺任意业务的恰好一次变换。
- observer 专属代码、配置与用例在 M2-01 清理；仍验证公共存储与插件行为的测试保留，不为 Admin 另建观察数据库。
- 模拟工具无真实外部副作用；调用记录故障验证使用受控提供者。平台模拟服务只覆盖当前协议交互，不构造完整聊天平台。

读取循环不重入；忙时合并唤醒，空闲时按测试默认 1 秒补查，读取错误有界退避。终止信号停止新读取，等待本地提交；未确认的输入保留标记。

## 6. 能保证的范围

要验证当前存储中的事件续读、正常自动触发、未决输入阻止自动重放，以及同一调用意图的核心去重。接受结果不确定时需要人工处置，也可能最终没有回复。

这不证明来源离线窗口完整采集、平台端恰好一次、外部工具完全受控或状态删除/回滚后仍不重复。对应 T03、T06、T07、T08；实际状态见[验收](../progress/validation.md)。

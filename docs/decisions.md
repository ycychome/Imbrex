# 架构决策记录

统一开发基线 0.3；M2 方案更新于 2026-10-20。MCP、ACP Consumer、OneBot 和离线恢复已实现；M2-01 的协议插件化、基础管理 API 与前端骨架已实现，M2-02/03/04 的观测、控制与打包验收仍待实现。运行保证仍以实际测试为准。

## 1. 主要设计取舍

| 议题 | 最终选择 | 理由与影响 |
| --- | --- | --- |
| 产品与交付 | Cordis + 事件/能力双通道，真实 QQ 闭环与管理控制台 | M2 取消 G05/observer 交付，优先解决实际观测、配置和异常处置需求 |
| 插件入口 | 一个由宿主绑定的 Imbrex 客户端，提供 events/capabilities 两组 API | 领域服务分离并绑定主体，不同时维护多组同义插件入口 |
| 数据库 | node:sqlite + DB worker；三张核心表 metadata/events/calls | 采用明确的最小表职责；保留完整 event_json，避免丢失可选事件属性 |
| 同步设置 | WAL + synchronous=FULL | 不采用把 NORMAL 描述成断电持久保证的措辞；FULL 的真实环境效果仍须验证 |
| 事件与读取 | first-write-wins、bigint/string、store_id、短事务 through_seq | 保留共同协议；精确规定满页/空页，不恢复签名游标和复杂 GC |
| store_id 范围 | 读取、发布、调用及调用查询均绑定预期存储 | 防止旧客户端在重建后把旧意图送到新存储，仍只有一个标识 |
| 参数与默认值 | HTTP 契约集中规定，分页默认 50、最大 100 | 选有界原型值，不将示例参数作为性能保证 |
| 回复工具 | 实例化 ID + input_event_ref/text；按实际 caller 权限读输入 | 不接受模型任意填写目标，也不借用连接器更大的读取权限 |
| 调用结果 | 全部已有状态都返回原记录；unknown 不自动重发 | 补全失败/未知状态的同键重试分支，避免状态机落入再次执行 |
| HTTP 状态 | 协议错误与 call.status 分开 | 有效调用记录可用 200 返回失败/未知；不是 200 就等于发送成功 |
| 源码与模板 | 采用锁定版本核验过的 Cordis 机制，模板在 M0 编译 | 不混用不同版本教程的 Schema、ready/dispose 与事件 API |
| 通知与恢复 | 通知只唤醒；Consumer 保存位置、会话关联与未决输入 | 未确认的 prompt 暂停，不用重跑模型来恢复；其他应用选择自己的状态策略 |
| QQ 接入 | 一个 onebot-v11 插件，具体服务实现可替换 | NapCat/SnowLuma 是候选实现，不是内核或插件类型 |
| Agent 接入 | MCP 提供上下文与工具，普通 Consumer 用 ACP stdio 提交输入 | 首接复用 pi/pi-acp，不自建 Agent、Runner 或协议桥接平台 |
| 文档治理 | docs 是唯一正式文档，旧稿本地忽略归档 | 开发者使用同一套可追踪的接口与设计依据 |

## 2. 已采用的决策

| 编号 | 决策 | 代价/边界 |
| --- | --- | --- |
| D01 | 信息网关与自主应用；QQ 是首个闭环 | 平台与模型逻辑留在连接器/应用，不设前台角色 |
| D02 | Cordis 装配 + 独立内核 + 薄适配 | 同进程受信代码共享故障域，不是安全沙箱 |
| D03 | TypeScript/Node、SQLite、单 worker、Linux 单实例入口 | 实际依赖与锁行为在 M0 验证，不预建可替换底座 |
| D04 | JSON 事件信封与 source/id first-write-wins | 不验证重复正文等价，不保留原 JSON 字节 |
| D05 | bigint 序号、线上字符串、单 store_id | 不能自动识别未换标识的旧备份回滚 |
| D06 | 主动拉取 + 可丢失唤醒 | 无 ACK、租约或托管投递保证 |
| D07 | 显式能力、稳定 call_id 与结果查询 | unknown 停止自动重发，接受某些回复未自动完成 |
| D08 | 静态主体、来源和能力范围 | 接入方可见总体日志位置，多租户隔离后置 |
| D09 | 应用自主选择状态；ACP Consumer 在 api.dataDir 保存进度、会话关联与 in_flight | 取代参考 Agent 决策库要求；未决输入需人工处置，不保证完全无人值守恢复 |
| D10 | 首版无事件/调用记录自动删除 | 持续占用增长，实际清理前补保留与去重期限契约 |
| D11 | M0—M2 + T01—T09，测试跟随真实功能 | 不把附件或灾难恢复变成首版前置 |
| D12 | 有限插件管理、可运行模板和必要演示；M2 增加后台 | 无市场、在线安装或任意配置/代码无损热更新保证 |
| D13 | OneBot v11 标准优先、实现差异显式收敛 | 不承诺 v12 或全部实现功能兼容；切换实现须检查身份范围 |
| D14 | MCP adapter 在现有 HTTP 监听提供 /v1/mcp，直接复用核心服务与 Principal 授权 | M1 只实现 Streamable HTTP；发现过滤不代替执行鉴权，不全量暴露原始 Action |
| D15 | acp-consumer 是现有消费者角色的具体插件，ACP stdio 首接 pi-acp | 插件管理所拥有的进程和输入责任；模型、上下文与历史归 Agent，不预建远程传输或通用调度 |
| D16 | M2-01 一次移除 adapters，拆成 server-http/api-rest/adapter-mcp；acp-consumer 更名 agent-chat | 原 REST/MCP 语义不变；可注销路由与依赖就绪有验证；稳定实例、数据和会话须迁移保留 |
| D17 | 取消 G05 与 observer 产品交付，T08 调整为管理与配置验收 | 删除专属示例/测试，保留公共行为用例；不为后台另建事件副本 |
| D18 | 宿主常驻 AdminRegistry，业务按实例登记，Admin 按需消费；Vue 3 + Vite + TailwindCSS | Admin 启停不改变业务生命周期；仅交付现有插件需要的声明式面板，不做 iframe 生态 |
| D19 | 管理员使用 admin:inspect/admin:operate 和 token_env，管理 API 独立于 Agent MCP | 不以 loopback 免密，不扩大原 /v1 主体权限；管理页面不回显秘密 |
| D20 | filter 仅在轮次完成并提交进度后更新绑定，历史不回放 | 异常未决先处置；不联动 OneBot 采集和 Principal 授权，不承诺任意参数热改 |
| D21 | 托管模型、窗口和提示词可编辑，保存后只受控重启 Agent | 宿主与 OneBot/HTTP 连续运行；会话证据保留，恢复失败显式重置；配置声明与实际观察分开 |
| D22 | 在线恢复由宿主协调目标 Consumer，保留备份和精确未决输入核验 | 不执行争用宿主锁的离线 CLI；确认消费不等于发送成功，unknown 不篡改、不自动重发 |
| D23 | M2-01 管理前端采用零第三方 UI 组件库：原生 HTML + Tailwind，单 `App.vue`；`web/` 是 npm workspace 构建包，不是 Cordis 插件 | 避免为三个字段引入中后台组件树和原子组件层；admin 插件默认按包名解析 `@imbrex/admin-web/dist`，`assets_dir` 仅覆盖；缺失资产 404 不阻塞；前端构建先于全量测试，体积预算在 M2-04 实测 |
| D24 | M2-02 起管理前端采用浏览器端 Cordis Shell：`ctx.views` 注册表、插件 loader 与渲染插槽；views 由插件 `client/` 自携 ESM 注册，Shell 不硬编码业务页面或路由；hash 仅表示当前视图 | 插件禁用/卸载时页面与导航消失；不污染服务端路由，不做 SPA 回落；继续不引入第三方 UI 组件库或状态库；Token 存 sessionStorage，轮询由各插件视图提供 |
| D25 | 控制台前端视图解耦与所有权：Views as Plugins，Shell 仅作为宿主外壳 | 坚决反对在 web/ 中集中硬编码业务视图。Cordis 核心哲学为 Everything is a plugin，视图所有权属于各业务插件（自携前端扩展或动态声明）。当前代码树内建的只读页面属于 M2 观测期过渡形态；演进目标锁定为「插件自编译前端 ESM + 浏览器端动态 import() 按需装配」，严禁将网关做成封闭硬编码的传统单体 SaaS 网站。 |

D13 不要求为每个实现写一套插件，也不要求预先建设通用协议框架。标准路径优先，遇到实际差异再增加小的兼容适配。

D09、D14、D15 的具体边界见 [Agent 接入](agent-integration.md)与[应用恢复](applications.md)。正常 end_turn 表示一轮结束，动作结果仍以核心 calls 为准；稳定 call_id 不使重跑整个 prompt 安全。

D16—D25 取代原 M2 第二消费者交付安排，完整管理契约见 [Admin](admin.md)。现有 M1 目录与命令在对应实现迁移前仍有效；不批量改写旧实验记录。M2 按观测、控制、打包验收推进，目标版本 v0.2.0 在验收后冻结。

## 3. 进入开发的条件

技术方向已足够明确。常规字段、状态、默认值和模块组织按本套文档实施；真正缺少的产品信息见[待决事项](open-questions.md)，按影响阶段解决。

依赖版本或协议行为出现新证据时，记录受影响契约、改变原因及必要测试。旧设计不会因保存在私有归档里重新成为实现要求。

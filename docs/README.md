# Imbrex 开发文档

**统一开发基线：0.3。状态：M0 核心原型与运行验收已完成；M1 的 OneBot、MCP、ACP Consumer 与离线恢复工具已实现。M2 已于 2026-10-20 定稿为全插件化与总控管理后台，先观测、后控制；协议插件与管理 API 骨架已实现，完整管理后台尚未交付。** 公开 M1 证据见下方运行记录，不将 M2 目标写成已具备能力。

安装、构建与运行见[本地开发与工程基线](development.md)，实际 M0 覆盖范围见[运行验收](experiments/m0-runtime.md)。
M1 的人工恢复命令与两阶段接入步骤见[接入与恢复记录](experiments/m1-operations.md)，真实服务实际覆盖与未验证范围见[真实验证记录](experiments/m1-live.md)。

Imbrex 是基于 Cordis 的可扩展事件与能力网关。插件接入事实，内核保存可重读事件，独立应用按自己的节奏处理，需要产生动作时调用获授权的能力。

第一版交付：**基础内核、Cordis 插件系统、必要演示插件、QQ → Agent → 按需回复闭环，以及可观测、可配置、可人工处置异常的管理后台。** 原 G05 第二消费者与 observer 产品交付已取消。NapCat、SnowLuma 是可提供 OneBot v11 接口的服务实现；Imbrex 不依赖它们的私有 SDK 或数据库。

## 文档收录与脱敏

- 纳入 Git：当前架构和接口契约、开发与验收计划、仍有效的决策及公开技术来源；实际验收记录须可复现且已脱敏。
- 不纳入正式文档提交：讨论逐字稿、重复或废弃方案、原始日志、真实消息、部署配置、账号与凭据。docs/disc/ 中的工作讨论应提炼后再归档，既有 disc 已转入本地私有归档；个人运维材料归 .private/。正式文档独立陈述已采用契约，不依赖这些材料。
- 待决事项只记录需要确认的信息类别与阻塞范围，不回填真实地址、账号、会话白名单或密钥。公开验收记录使用一致的替代标识，避免通过事件引用还原真实身份。
- 示例中的账号、会话、UUID、消息和端口均为虚构测试值；认证示例只引用环境变量名。公开来源 URL 和固定版本可保留，个人路径、内网地址及带认证参数的 URL 不可提交。

## 第一版采用的选择

- Cordis 装配，普通内核模块独立；插件受信、外部应用自主。
- TypeScript/Node.js，单网关 SQLite，数据库 worker 串行短事务。
- JSON-only CloudEvents 子集；source+id；first-write-wins；外层 parents。
- 内部 bigint、线上十进制字符串、单 store_id；不使用 JCS/fp1 或签名游标。
- 主动读取，通知仅唤醒；M1 通过 MCP 提供上下文与能力，通过 ACP stdio 驱动现成 Agent；事件订阅 SSE 按实际需求加入。
- 能力既可只读也可产生外部效果；外部写要求稳定 call_id，unknown 不自动重发。
- `onebot-v11` 插件负责标准协议与 QQ 映射，具体实现差异限于显式兼容适配。
- `agent-chat` 保存会话关联、消费进度与未决输入，异常未确认时暂停；模型循环和历史首接复用 pi/pi-acp。
- M2-01 一次将外部协议收敛到 plugins，acp-consumer 更名 agent-chat，删除 observer；core 保持不依赖网络/宿主框架。
- M2 使用宿主 AdminRegistry、显式管理权限和 Vue 3 + Vite + TailwindCSS 控制台；filter 在轮次边界应用，模型/窗口/提示词经受控 Agent 重启应用。
- 不自动 GC，不建设 B1/B2/C、附件归档、工作流平台、插件市场或高可用集群。

## 开发完成与保证范围

完成第一版意味着能加载插件、经明确的 OneBot v11 服务接入指定会话，让 Agent 决定回复或不回复；管理员可以观察真实状态、应用托管配置并处置未决输入。数据接纳、重复、重启与未知结果按契约可解释。

不由此承诺所有来源完整采集、任意应用至少一次处理、真实平台恰好一次、永久保留或主机灾难恢复。具体实现仅在对应测试通过后列为运行兼容，不因名称是 OneBot 就宣称全部功能相同。

M2 范围与退出条件见[开发计划](development-plan.md#m2)，M1 未覆盖的真实场景仍按授权补充。M2 目标版本 v0.2.0 仅在完整验收后冻结，当前文档修订不代表产品已经升级或发布。

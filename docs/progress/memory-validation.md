# Memory 真实验证记录

2026-10-22，在隔离的合成事件、独立 SQLite 账本和 Neo4j 容器中进行测试。没有连接真实 QQ 账号，也没有部署或合并 PR。

## 测试边界与预算

使用真实 DeepSeek `deepseek-flash` API 抽取与读图。Graphiti 为官方 `graphiti-core==0.31.2`，Neo4j 为 `5.26.24-community`。DeepSeek 的模型列表未提供 embedding；本地 CPU 运行真实 `BAAI/bge-small-zh-v1.5`，固定 revision `7999e1d3359715c523056ef9478215996d62a620`，采用 CLS/L2、512 维向量，经独立兼容接口接入。没有用随机、哈希或模拟向量替代真实 embedding。

测试经实际 Python 私有 FastAPI 的认证、请求校验、持久队列、Graphiti 写入与检索执行；HTTP 使用进程内 ASGI transport。当前测试没有重新走 OneBot 平台、完整 TypeScript 宿主、REST/MCP 网关或 ACP。相应授权与 Agent 行为由独立自动化测试覆盖，不能称为这次真实模型调用的端到端覆盖。

首轮预算上限 1 元；用户随后授权第二轮新增上限 2 元，累计上限 3 元。所有付费请求串行转发，单独限定模型、请求数、输入资源及输出 Token；发送前按 Flash 高峰价输入 2 元/百万 Token、输出 8 元/百万 Token 预留，确定 usage 后结算；未知响应保留预留，超过预算不出站。金额采用高峰价保守估算，最终余额差另行核对。密钥仅在被忽略的本地私有配置中，未写入代码、夹具或 PR。

模型格式及计费资料：[DeepSeek 图像协议](https://api-docs.deepseek.com/guides/vision/)、[价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、[BGE 模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)。资料只用于明确配置，不按模型名猜测运行时能力。

## 冻结的质量口径

使用仓库中 30 个独立 QA，其中 5 个图像梗。预期答案不进入抽取、图谱或检索请求。每题必须在服务 top-5 当前有效记忆中找到足够支持全部必要事实的证据才计 1 分；复合问题缺任何必要事实计 0 分。标点、空格和等价表述不影响评分。原始事件或 OCR 中有答案、但没有检索出来，不能算命中；查询 stale 也不能作为成功证据。

正式调用前修正了无图片却预设“猫”的 qa09，以及长期/周五前/加班等超出证据的表述。首轮对图片只提交题目；这导致同群五图中“这张图”的指代歧义。复测给五个图片题增加原先就存在的中性场景描述，不提供图中文字、预期解释或答案。报告保留这个口径差异，不把两轮当作完全相同的输入。

## 首轮

结果 **8/30**，未达到 27/30 门槛。命中 qa02、qa03、qa07、qa08、qa15、qa16、qa17、qa23，其余失败。32 条有效记忆中存在多条正确事实，但旧排序把任意 Graphiti episode 命中置于词汇证据之前，使多数相关记忆未进入 top-5。

5 张图的真实识别均完成、无失败图块，分别正确读出“又是周一”“我来找一个分号”“最后一点马上好”“1% 我还能再开一个会”“冲突解决了，恐龙还在”。图像识别完成不代表梗记忆检索通过；首轮图片题仅 qa15 命中。

8 条自动摄取因 `invalid_extraction` 被拒绝。隔离重跑抽取诊断时，qa19 输出裸账号 `10001`、qa24 输出 `90009`，而不是完整人物 ID；服务按边界要求拒绝。输入同时包含原账号和完整人物 ID 是可消除的歧义，不能通过自动补前缀或放宽校验绕过。

## 据此修复

- 为抽取显式配置 `json_object/json_schema`、输出硬上限和可选 reasoning；DeepSeek 对旧 `json_schema` 请求的真实 400 已复现。Graphiti 内部显式请求更高输出量时，也受配置硬上限约束。视觉输出仍独立受其 profile 管理。
- 从模型输入移除原账号，列出本批完整人物 ID 白名单；允许保存单次具体事实、安排与规则，保留不执行输入命令的边界。抽取契约纳入 fingerprint，升级须维护重建。
- 在任何 Graphiti 写入之前验证整批候选。回归已复现旧代码对第二条非法候选报错前写出第一条候选的问题。
- 以授权范围内的 BM25 和有限 Graphiti 加分融合排序。回归覆盖具体中文事实被泛图谱命中挤出、无词汇重合时继续使用图谱的情形。
- 显式维护重建可在新 generation 恢复已持久接收但抽取被拒的 ingest；普通消费不自动重试，墓碑和人工修订仍受保护。

## 真实专项

使用额外隔离的合成会话和同一真实模型验证了：同昵称不同账号保持不同人物；昵称变更保留同一人物和时间别名；同账号跨群身份一致、记忆仍属于各自会话；跨 scope 读取返回 404；非原调用者读取操作返回 404；错误服务 token 返回 403。版本冲突没有覆盖主动修正。遗忘后重放原摄取操作和重建均未复活记忆，原始事件仍保留。

这验证的是 Python 私有服务的身份、范围及操作边界。公开维护能力的 Principal 授权、来源伪造防御和 Agent 上下文边界仍由网关自动化测试证明，不能把共享服务 token 当作普通 Agent 凭据。

大图测试走实际下载、解码、预处理、真实视觉 API 和结果缓存：

原图没有被旧的 8 MiB 或 20 MP 门槛直接拒绝。实际档案使用 DeepSeek 已验证格式、8192 单边上限、每图至多 1024 image Token，以及更保守的 16 MiB 请求预算；主机解码预算独立设置为 128 MiB。再次读取同一结果未增加 API 请求；档案变化产生不同 variant key，并利用仍在缓存的原图重新处理。

测试中还保留了两次受控异常：60 秒整次重建预算导致任务 unknown，随后用 600 秒维护预算在新 generation 完成重建（91.26 秒）；最初图像测试的累计代理载荷预算只放行整体预览、阻止后续 OCR，服务正确返回 partial。调整测试资源预算和每请求能力档案后重新处理成功。没有在结果未知的原命名空间盲目重跑。

## 用量、检查与剩余范围

总计 **318 次成功模型请求**（含 1 次 9 Token 最小探测），实际 usage 合计输入 **1,136,244 Token**、输出 **19,743 Token**。按高峰价并把全部输入视为未命中缓存，保守费用上界为 **2.430432 元**，低于累计 3 元预算；测试前后接口余额减少 **0.94 元**。余额差是该时间段的账户观测值，逐请求 Token 和保守费用上界另有本地账本记录。首个测试网关因无可用通道拒绝请求，其用量查询仍为 0。

代码验证：本地 TypeScript typecheck、Python ruff/mypy、**45 项 pytest** 全部通过，含真实 Graphiti/Neo4j 与受控模型集成。功能提交 `6656ef5c97be2a96e5f9aa754db7585f853e65ae` 的 [CI #70](https://github.com/ycychome/Imbrex/actions/runs/39702578849) 通过 `check`（`npm run check`）和 `memory`；独立 Luna 只读审查未发现阻塞问题，覆盖模型请求边界、排序、整批校验、恢复、墓碑与人工修订保护。

这次使用并调优了预先定义的合成验收集，结果不代表对未知真实群聊的泛化测量；尚未进行真实 QQ 账号与 Agent 的完整端到端验证、大规模历史回填/重建压测，也未覆盖全部供应商能力档案。当前仍有 qa03 语义召回漏项。GIF 首帧限制和未接入管理页面的范围保持不变。OpenAI SDK 的私有请求构造 hook 受锁定版本及实际 HTTP 回归保护，升级 SDK 时须重新核对。

# 验证与验收

本页定义验证方式、九组验收用例（T01—T09）、M2 退出检查与证据格式。哪些已通过、还差哪些见[项目状态](status.md)；阶段安排见[开发计划](plan.md)。

验收结论写在本页，原始运行记录不入 Git，只保留[证据索引](#9-证据索引)。

## 1. 验证方式

2026-10-20 修订 M2 验收目标：移除原 G05 第二消费者产品门槛，T08 改为管理控制台、配置应用与在线处置验收。旧 M0/M1 实验记录保留当时范围；M2-01 的协议迁移、基础管理静态页和缺失资产降级已有自动化测试，M2-02/03/04 仍待验证，不能由已有测试通过推导为完整 M2 完成。

测试跟随功能交付，不先建设独立故障仿真平台。采用内置测试工具、临时数据目录、可控时钟和几个精确中断点；模拟提供者记录实际调用次数。真实 QQ 验证使用明确授权范围，不能用模拟成功替代真实覆盖。

独立预期在执行前生成：哪些输入、预期身份和输出、哪些发送应发生、哪些结果应保持未知。不能从系统实际输出反推“期望就是这些”。

## 3. 需要保留的几个反例

### 3.1 提交成功但通知失败

提供者已收到 created；某个监听器抛错或返回拒绝 Promise；重读应取得已提交事件，同身份重试返回 duplicate_identity。错误不能变成第二条业务事件，也不能把已提交结果改为“未接纳”。

### 3.2 满页后还有匹配

固定页上界内匹配 102/120/160，limit=2；返回 102/120，next_after_seq=120，caught_up=false。后续读取才能推进到上界。空过滤结果则可以推进到已完整查询的上界。

### 3.3 平台可能已发送，网关未保存成功

模拟 handler 记录一次发送后，注入响应或结果提交失败。应用查询原 call_id，恢复后保留 unknown；测试不要求自动补发，也不得重新生成意图使调用次数变二。

### 3.4 Agent 可能已回复，Consumer 尚未保存完成进度

模拟 Agent 经 MCP 发出一次 reply，在 ACP 最终响应到达前或 Consumer 提交完成进度前中断。重启必须读到 in_flight 并保持不可用，不再发送这条输入的 prompt；查到原调用也不能据此重跑整轮模型。人工核验后按精确输入处置，验证后续消费不越过未处理输入。另验证正常 end_turn 与 last_seq/清除标记一起保存后的续读。

## 4. 证据格式

每份记录包含：T 编号、提交/依赖版本、OS 与存储配置、输入与独立预期、执行步骤或中断位置、实际结果、支持的结论与已知限制。日志中的真实消息与凭据需最小化和脱敏。

M0-01 的工程基线见[开发与工程基线](../ops/development.md)。独立实验记录保存在本地私有归档，不入 Git，其覆盖范围登记在[证据索引](#9-证据索引)。T04/T07 的真实接入部分缺账号或 Agent 时标记待验证，不能删除用例后宣称完成 M1。

## 5. 不由首版测试证明的事情

- 进程 kill/restart 不等于断电、文件系统损坏或主机损毁恢复。
- 正常 QQ 入站不等于全部历史、自发消息、附件、编辑撤回都完整采集。
- 模拟平台只派发一次不等于真实平台端恰好一次。
- 单所有者权限测试不等于多租户隔离或不受信插件沙箱。
- 短期低流量演示不等于长期容量与性能目标满足。

这些能力有真实需求时再选择目标并增加相应验证，不能沿用未经验证的保证。

## 6. 文档与提交检查

纯文档变更检查相对链接、代码围栏、JSON/SQL 示例、表格和 Git diff。代码变更完成类型检查、受影响的必要测试及运行说明。依赖或行为改变时更新相应规范和决策；通过当前阶段后继续下一项，不无理由扩大测试范围。

## 7. OneBot 兼容性验收

区分标准夹具通过与真实服务通过。T09 先以不同实现标识和已知合法表示测试同一标准路径；M1 用一个用户提供的 OneBot v11 服务完成真实闭环。另一个实现可用时复用同一测试，不修改 Agent 协议或内核代码；未实际连接就保持未验证。

实现差异、扩展动作和身份连续性要分别记录。一次普通消息收发不能代表历史、材料、自发回流或所有协议版本都兼容。不得用“支持 OneBot”替代具体的实现版本、传输模式和能力清单。

## 8. M2 退出检查

| 阶段 | 需要验证的真实风险与通过条件 |
| --- | --- |
| M2-01 协议迁移 | 一次移除 adapters、迁移 agent-chat、清理 observer 专属代码/配置/测试；保留有效的 M1 回归及 REST/MCP 路径、鉴权、seq/call_id 和结果语义；示例和迁移说明对应实际代码 |
| M2-01 管理静态页 | 前端 workspace 类型检查与构建通过；真实 Host 默认解析 `ui-contract/dist`，`/admin` 与资源返回 200，`/api/admin/info` 鉴权与序号语义不变；显式 `assets_dir` 缺失时 `/admin` 404 且 admin API/宿主不中断；1–2 MB 体积预算在 M2-04 实测记录 |
| M2-01 路由与就绪 | 协议卸载即注销路由/静态映射，无重复注册；TCP 已监听但 MCP 路由未注册时不投递；依赖卸载时停止新投递；在途外部调用仍保存结果 |
| M2-02 管理认证 | 无凭据及普通 Agent 凭据不可读写管理资源；admin:inspect 无操作权限；跨主体审计只在专属管理入口；配置/日志/页面不泄漏秘密 |
| M2-02 注册与观测 | 同模块多实例面板独立；Admin 晚启用、重启、卸载不重启业务；正常 in_flight 显示 processing，异常未决与停止原因分别可见；序号距离不显示为消息数，正常不回复不报错 |
| M2-03 filter 应用 | 处理中保存新值，旧轮保持旧配置/超时；轮次提交后应用新绑定，包括已预读未处理的页内记录；历史不回放；不扩大采集/授权；未决阻止应用；部分写入失败不得伪报成功 |
| M2-03 在线处置 | 使用真实 Host 与受控 Agent 制造未决，宿主不停机处置精确输入；备份和原因先于状态更新；旧页面/重复处置不得推进下一条；失败保留可核验状态；unknown 不修改为成功、不自动补发 |
| M2-03 会话与配置 | 模型/窗口/提示词保存后显示待重启；无活跃轮次且无异常未决时只重启 Agent；HTTP/WS 和其他插件保持运行；原会话证据保留，新轮实际使用新配置；load 失败报告并显式重置 |
| M2-03 单会话重置 | 活跃或未决会话拒绝重置；合法操作仅解除目标 source 的持久/内存关联，不删历史、不改变其他会话和消费位置 |
| M2-04 交付 | 在干净环境安装依赖并构建，单个网关启动命令提供 API 与后台；浏览器完成观测/配置/处置流程；记录 SPA 压缩后资产体积；部署与迁移命令实测，验收后冻结 v0.2.0 |

这些用例按功能实际风险落地，不为常量或纯展示文案写镜像测试。T01—T07/T09 的公共行为继续有效，只有 observer 专属交付被取消；M2 不移除未决记录、进程清理和未知发送的故障用例。

观测、模拟故障和获授权的真实服务演练分开记录。不得在未获得对应范围授权时制造真实丢响应、重复发送或修改运行账户。M2 完成要求 G01—G04、G06、G07 均有证据；没有长期运行证据就保留长期可靠性限制。
